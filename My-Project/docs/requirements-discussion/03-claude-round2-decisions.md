## 3. 针对 Codex 六项风险的修正决定

### 风险 2：“上传时原样”的边界
- 已在 pynetdicom 3.0.4 源码中核实：`Event.encoded_dataset(include_meta=False)` 返回 C-STORE P-DATA 中收到的**原始数据集编码字节**（`request.DataSet.getvalue()`）。`include_meta=True` 时，前面拼接的 128 字节前导、`DICM` 与 File Meta 是 **SCP 端按请求与表示上下文生成的**（MediaStorage UID、协商的传输语法、实现 UID），**不是设备源文件中的 File Meta**。
- 定义：
  - **基线 = B 收到的网络数据集字节**（`dataset_sha256`），不是设备源 Part-10 文件。
  - B 写盘的 Part-10 文件 = B 生成的 File Meta + 原样数据集字节（`file_sha256` 覆盖二者）。
- **不声称**接收了设备原文件的全部字节：设备端文件的传输语法、File Meta、前导都可能不同；若 SCU 为传输做了传输语法转换，网络字节本来就与设备文件不同。
- 用真实收发核验，测试 `TC-R5-P1`：发送端文件“File Meta 之后的字节”的 SHA-256 与 B 记录的 `dataset_sha256` 相等（同传输语法时），并断言 B 文件的 File Meta 中 ImplementationClassUID 是 B 的而不是发送端的。

### 风险 3：幂等重发必须先确认已有副本完整
重发同 SOP Instance UID 时，先对**已存文件**做完整性校验（基线 HMAC、文件哈希），再比较新来数据：
- 已存副本完整，新数据与基线 `dataset_sha256` 相同 → 0x0000（`duplicate-identical`）。
- 已存副本完整，新数据编码不同但内容等价（像素哈希、元数据快照相同）→ 0x0000（`duplicate-equivalent`）。
- 已存副本完整但内容不同 → 0xC010 冲突，隔离并告警。
- **已存副本缺失或被改** → **不报成功**：返回 0xC011，新数据入隔离区，告警 `STORED_COPY_DAMAGED`。不自动用新数据覆盖修复（D17）。

### 风险 4：审计与基线的防篡改边界
- 审计每条记录包含 `prev_hash` → `entry_hash`，并对 `entry_hash` 做 HMAC，没有密钥就无法伪造重算整条链。
- 另设**本机锚点文件**（`runtime/anchors/audit-anchor.log`，与数据库分开存放）：每次提交审计后追加 `seq + entry_hash + HMAC`。数据库尾部被截断时，锚点中的 seq 大于库中最大 seq，即可检出。
- 提供 `pacs audit head` 导出链头，用于**带外记录**（例如写进测试报告或纸面）；`pacs audit verify --expect-head SEQ:HASH` 用带外链头核对。
- **如实写明检测边界**：
  1. 同时截断数据库与锚点文件，且没有带外链头 → **检测不到**。
  2. 同时取得 HMAC 密钥与写权限的攻击者可以重算全链与基线 → **检测不到**。
  3. 密钥与数据库在同一台机器上，只能防“只能改数据目录、拿不到密钥目录”的攻击者。
- 不使用“绝对防篡改”之类表述。

### 风险 5：状态与文档一致
- **层级归属冲突**（Series 已属于另一 Study，或 Study 已属于另一 PatientID）→ 0xC003 拒绝。
- **落盘失败**（OSError）→ 0xA700；**事务失败** → 0xC0FF。二者都不留部分数据。
- **并发同 UID**：用按 UID 的锁串行化；先提交者胜，后到者走重复/冲突判定。
- **MOVE/GET 子操作失败** → 最终 0xB000（部分失败）或 0xA702（全部失败），并附 Failed SOP Instance UID List。
- **CANCEL** → 0xFE00，带剩余/完成/失败计数。
- **C-STORE 0x0000 ≠ Storage Commitment**：B 不实现 Storage Commitment Push Model（1.2.840.10008.1.20.1），其表示上下文会被拒绝（abstract syntax not supported），并有测试覆盖。接口文档明确：0x0000 只表示 B 已持久化并建立基线，**不构成** Storage Commitment 意义上的“安全保管承诺”，也不包含后续 N-EVENT-REPORT。

### 风险 6：证据级别
每条需求、每个声明支持的 SOP 类，都标注证据级别：

| 级别 | 含义 |
|---|---|
| E0 | 仅声明未实测 |
| E1 | 单元测试 |
| E2 | pynetdicom 真实 TCP 回环（同库两端） |
| E3 | 独立实现（DCMTK）回环 |
| E4 | PyQt5 离屏自动化冒烟 |
| H | 真人操作验收（**未执行**，留给用户） |
| X | 跨组跨主机联调（**未执行**，留模板） |

关于 5h：5h 是额度**重置窗口**，不是 5 小时计算时长；本项目不做任何“已向用户收费”的陈述，也无法得知剩余额度。

## 4. 新增或调整的点（相对第一轮）
1. 重复判定新增“内容等价但编码不同”分支（例如首次用 Explicit VR LE 发送，重发用 Implicit VR LE）。
2. 角色权限在**关联协商阶段**按表示上下文过滤：无 QUERY 角色的对端，其 C-FIND 上下文被拒；无 RETRIEVE 角色的对端，其 MOVE/GET 上下文被拒，并告警“未授权检索请求”。处理器内再做一次权限复核（纵深防御）。
3. 越权 C-MOVE（目的地未登记或无 MOVE_DEST 角色）→ 0xA801，且 B **不会发起任何外连**。
4. 不再使用第一轮暂定的 0x0111 / 0x0124：越权在协商阶段处理；冲突类失败统一放在 PS3.4 C-STORE 失败类 Cxxx 区段，并附 ErrorComment，在接口文档中逐码说明。
5. 白名单变更前后值、告警确认都写入审计；告警按“类别 + 对象”聚合，重复核查不会刷屏。
